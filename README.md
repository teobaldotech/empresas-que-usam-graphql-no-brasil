## 🎯 Sobre o projeto

Este repositório reúne registros colaborativos de empresas, organizações e projetos relacionados ao GraphQL no Brasil.

A proposta é facilitar o acesso a informações úteis para profissionais de tecnologia, estudantes, recrutadores e pessoas interessadas no ecossistema GraphQL.

O catálogo pode ajudar a:

* Descobrir organizações com experiências documentadas em GraphQL.
* Conhecer projetos e tecnologias relacionados ao desenvolvimento de APIs.
* Encontrar referências para estudos e projetos pessoais.
* Identificar organizações para pesquisas profissionais e oportunidades de carreira.
* Compartilhar experiências e contribuir com informações verificáveis.
* Acompanhar a evolução do uso de GraphQL no mercado brasileiro.

O repositório é comunitário e não representa um diretório oficial de empresas usuárias de GraphQL.

**Importante:** os registros históricos deste catálogo não significam, necessariamente, que determinada empresa utiliza GraphQL atualmente. A comprovação deve ser feita por registro e por meio de fontes públicas confiáveis.

## 🧭 Objetivos

### Transparência

Diferenciar informações verificadas, registros históricos e dados que precisam de confirmação.

### Qualidade

Evitar duplicações, links quebrados, atribuições tecnológicas sem fundamento e informações desatualizadas.

### Colaboração

Facilitar a participação de pessoas desenvolvedoras e da comunidade por meio de contribuições revisáveis.

### Manutenção

Incentivar a atualização periódica dos registros sem descartar informações históricas de maneira arbitrária.

## ⚠️ Status e confiabilidade dos dados

As empresas e tecnologias relacionadas neste repositório foram preservadas a partir dos registros históricos fornecidos para o catálogo.

**A lista ainda precisa de uma revisão individual para que cada empresa possa receber um status de verificação.** A presença de uma organização na tabela não constitui comprovação de uso atual de GraphQL.

Para evitar interpretações incorretas, adote as seguintes categorias durante a manutenção:

| Status           | Significado                                                                     |
| ---------------- | ------------------------------------------------------------------------------- |
| `Verificado`     | Existe uma fonte pública que demonstra a relação da organização com GraphQL.    |
| `Histórico`      | O registro foi preservado de uma versão anterior, mas ainda não foi revalidado. |
| `Pendente`       | Há uma fonte ou indicação inicial que precisa ser examinada.                    |
| `Não confirmado` | As fontes consultadas não foram suficientes para confirmar a relação.           |

Essas categorias são uma proposta de manutenção. Elas não significam que as empresas já tenham sido verificadas ou classificadas individualmente.

### O que conta como evidência?

São exemplos de evidências úteis:

* Documentação técnica pública da própria organização.
* Repositórios oficiais com esquemas GraphQL, consultas, resolvers ou integrações identificáveis.
* Artigos técnicos publicados por equipes da organização.
* Apresentações técnicas com autoria e contexto verificáveis.
* Vagas ou descrições técnicas que mencionem explicitamente GraphQL.
* Estudos de caso públicos que identifiquem o uso da tecnologia.

Uma menção antiga pode demonstrar uso histórico, mas não comprova necessariamente uso atual.

### O que não é suficiente?

Isoladamente, os seguintes elementos não comprovam que uma empresa utiliza GraphQL:

* Uso de React, React Native, Vue ou Angular.
* Uso de Redux, MobX ou outras ferramentas de gerenciamento de estado.
* Uso de Node.js, TypeScript ou outras tecnologias de backend.
* Uso de Apollo sem contexto que demonstre a relação com GraphQL.
* Uma vaga genérica de desenvolvimento frontend.
* Uma lista de tecnologias sem fonte identificável.

O GraphQL pode ser utilizado com diversas linguagens e frameworks. A tecnologia específica utilizada no frontend não é suficiente para determinar a arquitetura da API.

## 🔎 Como pesquisar

Para encontrar uma empresa ou projeto:

1. Utilize a busca do GitHub para pesquisar o nome.
2. Consulte o site oficial da organização.
3. Procure documentação, repositórios ou artigos técnicos que mencionem GraphQL explicitamente.
4. Verifique se a evidência corresponde ao uso histórico ou atual.
5. Consulte as issues abertas antes de propor um novo registro.

Links úteis:

* [Issues abertas](https://github.com/graphql-brasil/empresas-que-usam-graphql-no-brasil/issues)

## 🤝 Como contribuir

Contribuições são bem-vindas! Você pode adicionar empresas e projetos, corrigir informações, verificar registros históricos ou melhorar a documentação.

Leia o [CONTRIBUTING.md](CONTRIBUTING.md) antes de enviar sua alteração.

### Fluxo recomendado

1. Pesquise o registro existente para evitar duplicatas.
2. Identifique uma fonte pública que sustente a alteração.
3. Faça um fork do repositório.
4. Crie uma branch específica para a mudança.
5. Atualize o registro sem alterar informações não relacionadas.
6. Revise os links, a grafia e a formatação Markdown.
7. Abra um Pull Request com um resumo das alterações e as respectivas fontes.

Não invente tecnologias, localidades, experiências profissionais ou informações sobre a arquitetura de uma empresa.

Se não houver evidência suficiente, proponha a correção como pendente de verificação, em vez de apresentar a informação como fato confirmado.

## ✅ Critérios de inclusão

Para incluir uma empresa ou projeto como usuário de GraphQL verificado, a contribuição deve apresentar:

* **Identificação:** nome oficial ou nome público reconhecível da organização.
* **Fonte:** URL pública que permita examinar a evidência.
* **Relação com GraphQL:** descrição objetiva do uso identificado.
* **Contexto temporal:** data da fonte ou informação disponível sobre quando o uso foi documentado.
* **Integridade:** informações coerentes com a fonte, sem extrapolações.
* **Ausência de duplicatas:** confirmação de que o registro não existe na lista.

### Evidências recomendadas

Prefira fontes oficiais e diretamente relacionadas à organização. Quando houver apenas fontes históricas ou indiretas, registre essa limitação.

Um registro pode ser mantido como histórico sem ser promovido a verificado.

## 🔬 Verificação dos registros

A revisão deve acontecer gradualmente, sem apagar os registros históricos apenas por falta de confirmação imediata.

### Procedimento de revisão

Para cada empresa:

1. Verifique se o site oficial está acessível.
2. Procure uma fonte que mencione GraphQL explicitamente.
3. Examine se a fonte descreve uma integração, um serviço, uma API ou um projeto real.
4. Registre a URL da evidência e a data da consulta.
5. Classifique o registro de acordo com a força da evidência.
6. Atualize ou corrija as informações quando houver fundamento.
7. Mantenha o registro como histórico ou não confirmado quando a evidência for insuficiente.

| Site oficial        | Página oficial da organização                     |
| Localização         | Cidade ou região, quando publicamente conhecida   |
